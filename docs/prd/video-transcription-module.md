# 원어 자막 초본 생성 모듈 PRD

문서 상태: 검토용 초안
작성 기준: 사용자와 확정한 현재 제품 결정
대상 범위: 전사 모듈만 해당하며 리서치·번역 모듈은 포함하지 않음

## 문제 정의

사용자는 한국어 YouTube 영상의 원어 자막을 직접 만든다. 현재는 영상의
발화를 처음부터 끝까지 듣고 옮기거나, 기존 자동 자막을 다시 확인하면서
누락·오인식·화자·화면 자막 문제를 직접 찾아야 한다. 이 과정은 반복 작업이
많고 시간이 오래 걸린다.

전사 모듈의 목적은 사람이 최종 자막을 완성하는 일을 대체하는 것이 아니다.
사용자가 바로 수정할 수 있는 원어 자막 초본을 빠르게 만들고, 자동으로
판단하기 어려운 구간만 눈에 띄게 제시해 전체 작업 시간을 줄이는 것이다.

사용자는 최종 결과를 직접 수정하지만, 수정 사유나 오류 종류를 일일이
기록할 여유는 없다. 따라서 초기 버전은 사용자의 수정 행동을 분석하거나
품질 데이터를 자동으로 축적하는 데까지 범위를 넓히지 않는다.

## 해결 방안

저장소 안에 전사 전용 에이전트 스킬과 Python CLI를 둔다. 사용자가
YouTube URL을 전달하면 에이전트 스킬이 고정된 초기 처리 흐름으로 CLI를
실행하고 다음 과정을 안내한다.

1. YouTube URL을 받은 뒤 전사를 시작하기 전에 사용자에게 회차 맥락을 묻는다.
2. 사용자가 이름·의상·외형을 자유로운 텍스트로 입력하면 이번 실행의 등장인물 참고 정보로 정리한다.
3. 영상, 기존 자막, 오디오 등 전사에 필요한 입력을 준비한다.
4. Apple M4에서 ASR과 VAD를 실행해 전체 시간대의 임시 발화 cue를 만든다.
5. 임시 전사 품질을 진입 조건으로 삼지 않고 영상 전체 시간대를 시각적으로 감사한다.
6. 화면 하단 자막의 문구와 등장·소멸 시점을 읽어 오디오·VAD·ASR cue를 맞추는 증거로 사용한다.
7. 전체 cue를 연속 구간으로 나눠 비전 에이전트가 회차 맥락, 앞뒤 대사, 화자, 행동, 화면 자막과 장면 연결을 함께 판정한다.
8. VAD로 찾은 누락 구간과 시청각 증거가 충돌하는 구간을 재전사한다.
9. 자동으로 확정하기 어려운 구간은 결과에서 명확하게 표시하고 사용자가 확인을 진행할지 먼저 묻는다.
10. 사용자가 동의하면 미확정 cue를 하나씩 확인하고, 답변하지 않아도 현재 JSON·CSV 초본을 제공한다.
11. 결과 파일의 필수 필드, 순서, 타임코드와 JSON·CSV 일치 여부를 검증한다.

전체 작업은 AI 에이전트가 전사 스킬의 런북을 따라 수행한다. Python CLI는
미디어 준비, ASR, 프레임 추출, 결과 병합과 검증처럼 재현 가능한 작업을
담당하고, ChatGPT 비전 에이전트는 영상 맥락과 화면 자막을 판정한다. 로컬
ASR은 전체 시스템의 실행 경계가 아니라 음성 초본을 만드는 한 도구다.

## 구현 결정

### 사용자 진입점

- 저장소의 에이전트 지침이 전사 요청을 전사 스킬로 연결한다.
- 전사 스킬은 사용자 요청을 런북 실행으로 바꾸고, CLI와 비전 감사 에이전트를 순서대로 조정한다.
- 전사 스킬은 유효한 URL을 받으면 실행 ID와 `waiting_context` 상태를 만들고, 다른 처리보다 먼저 회차 맥락 입력 턴을 연다.
- 사용자가 회차 맥락이나 `없음`으로 명시적으로 답하기 전에는 ASR·비전 감사처럼 비용이 드는 처리를 시작하지 않는다.
- 사용자가 자유롭게 입력한 문장을 이번 실행에서 공유할 등장인물 참고 정보로 정리한다.
- CLI는 에이전트의 시각 판단을 제외한 결정적인 미디어·파일 작업을 직접 재현할 수 있어야 한다.
- 도움말에서 입력, 실행 단계, 비전 감사 상태와 출력 위치를 확인할 수 있어야 한다.

### 처리 책임

초기 버전은 다음 다섯 책임을 갖는다. 이는 제품 동작의 구분이며 실제 코드의
파일·클래스·모듈 수를 강제하지 않는다. 구현이 더 단순하면 책임을 한 모듈에
합칠 수 있다.

1. **전사 실행**
   - URL을 입력받아 고정된 초기 처리 흐름을 시작한다.
   - 전사 시작 전에 회차 맥락 입력 턴을 진행하고 사용자 답변을 실행 기록에 보존한다.
   - 실행 ID를 만들고 전체 작업 상태를 관리한다.
   - 에이전트 런북에 따라 나머지 책임과 병렬 감사 에이전트를 조정한다.
   - ASR·VAD·프레임 추출·파일 형식의 세부 구현은 사용자에게 노출하지 않는다.

2. **입력 준비**
   - YouTube 원본, 기존 자막, 오디오와 전체 시간대의 시각 감사 자료를 준비한다.
   - 기존 자막은 선택적 증거로 취급한다. 자막이 없거나 다운로드·해석에 실패하면 경고를 남기고 ASR을 계속한다.
   - 원본 영상이나 오디오를 준비하지 못했을 때만 입력 준비를 실패 처리한다.
   - 로컬 ASR과 VAD 기반 누락 탐지를 수행한다.
   - 임시 cue와 전체 시간대의 시각 감사 자료를 만든다.
   - 비전 에이전트가 요청한 프레임, contact sheet와 짧은 클립을 추출한다.
   - 비전 감사가 찾은 대략적인 하단 자막 전환 구간 주변을 촘촘하게 다시 검사해 시간 경계를 좁힌다.
   - 성공한 준비 결과를 한 번에 실행 디렉터리에 반영하고, 실패한 중간 결과는 완료 결과처럼 노출하지 않는다.

3. **시각 맥락 감사**
   - 영상 전체 시간대와 모든 임시 cue를 감사 범위에 포함한다.
   - cue를 연속 구간으로 나눠 앞뒤 대사와 장면 맥락을 유지한 채 비전 에이전트에 배정한다.
   - 각 cue의 수정 권한을 가진 구간 에이전트를 하나만 지정한다.
   - 인접 구간 에이전트는 경계 cue를 읽기 전용 문맥으로만 보고 수정안을 제출하지 않는다.
   - 모든 비전 에이전트에 동일한 회차 맥락을 전달한다.
   - 사용자가 적은 이름·의상·외형과 화면 속 인물이 일치할 때 등장인물 후보로 사용한다.
   - 화자·청자·행동 주체·지시 대상·화면 하단 자막을 판정한다.
   - 장면 분석과 같은 비전 호출에서 화면 자막 문구와 대략적인 표시 구간을 함께 판정한다.
   - 보정된 화면 자막 구간과 오디오·VAD·ASR cue 사이의 정렬 증거를 생성한다.
   - 애매한 구간은 프레임 밀도를 높이거나 짧은 클립으로 다시 감사한다.
   - 메인 에이전트는 담당 구간의 판정을 채택하거나 거부하고, 애매하면 재감사 대상으로 보낸다.

4. **초본 완성**
   - 준비된 발화와 누락 복원 결과를 하나의 초본으로 합친다.
   - 음성 발화, 화면 자막과 비전 맥락 판단을 분리된 근거로 보존한다.
   - 불확실한 구간을 보존하고 필요한 확인 질문을 만든다.
   - 사용자 답변을 JSON 정본에 반영하고 여기서 CSV를 다시 생성한다.
   - 답변이 일부 없어도 `needs_confirmation` 상태의 초본을 생성한다.

5. **결과 검증**
   - 필수 필드, 연속된 순번, 정수 타임코드와 재생 시간을 검사한다.
   - JSON·CSV의 행이 동일한지 검사한다.
   - 모든 시간대와 cue에 시각 감사 기록이 있는지 검사한다.
   - 화면 자막을 근거로 조정한 cue TC에 프레임·PTS 증거가 있는지 검사한다.
   - 오류가 있으면 모든 위반을 사용자에게 보여주고 성공 상태를 기록하지 않는다.

ASR, VAD와 프레임 추출은 입력 준비 책임에서 사용하는 교체 가능한 도구로 둔다.
비전 감사는 모든 실행에서 수행되는 핵심 책임이며 선택 가능한 보조 단계가
아니다. 별도 OCR은 비전 모델이 화면 문구를 확정하지 못할 때만 사용하는
보조 도구로 둔다.

### 처리 모델

- 기본 ASR 엔진은 `mlx-whisper`다.
- 기본 모델은 `large-v3-turbo`다.
- 시청각 증거가 충돌하거나 초본을 확정하기 어려운 구간만 `large-v3`로 재전사한다.
- cue 구간의 기본 비전 감사는 `gpt-5.6-sol`을 사용한다.
- 특정 장면의 촘촘한 프레임 판정은 `gpt-5.6-terra`를 사용한다.
- 구간별 결과 취합과 재검증은 `gpt-5.6-sol`을 사용한다.
- 비전 모델은 사용자가 실행 중인 ChatGPT 에이전트 환경을 통해 사용한다.
- 외부 유료 ASR API 제공자 구현은 초기 범위에 포함하지 않는다.

### 회차 맥락 입력

- 전사 스킬은 URL을 받은 뒤 `waiting_context` 상태에서 회차 맥락을 한 번 묻는다.
- 초기 버전에서 받는 정보는 등장인물의 이름·의상·외형을 설명한 텍스트와 선택적인 화면 자막 신뢰도 덮어쓰기(`low`, `medium`, `high`)다.
- 사용자는 정해진 표를 채우지 않고 자유로운 문장이나 목록으로 입력할 수 있다.
- 명시적인 답변을 받기 전에는 ASR과 비전 감사를 시작하지 않는다.
- 사용자가 `없음`이라고 답하면 `processing`으로 전환해 전사를 계속하되 인물 이름을 추측하지 않는다.
- 원문 답변과 에이전트가 정리한 등장인물 목록을 모두 실행 기록에 보존한다.
- 정리된 회차 맥락은 모든 비전 감사 구간과 메인 재검증 단계에서 동일하게 사용한다.
- 외형 설명은 인물 식별의 참고 증거이며 단독 확정 근거가 아니다.
- 여러 인물이 설명과 비슷하거나 의상이 바뀌어 확신할 수 없으면 `미확인 인물`로 남긴다.
- 회차 맥락은 해당 실행에만 적용하고 다른 영상에 자동으로 재사용하지 않는다.

### 실행과 상태

- 모든 산출물은 실행 ID별로 분리한다.
- 작업 상태는 `waiting_context`, `processing`, `needs_confirmation`, `finalized`, `failed`로 구분한다.
- 파일 검증 상태는 `pending`, `valid`, `invalid`로 별도 기록한다.
- 형식이 유효한 초본에 미확정 cue가 남아 있으면 작업 상태는 `needs_confirmation`, 파일 검증 상태는 `valid`가 될 수 있다.
- 사용량과 처리 정보는 로컬 실행 기록에 누적한다.
- 실패 시 `failed` 상태와 중단 단계, 오류 메시지를 사용자에게 보여준다.
- 재실행이 기존의 정상 초본을 부분적으로 덮어쓰지 않도록 완료 파일은 원자적으로 교체한다.

### 초본과 확인

- 초본의 정본은 JSON이며 CSV는 검증된 JSON에서 생성한다.
- JSON과 CSV는 표현 방식이 달라도 같은 cue 행을 나타내야 한다.
- JSON cue는 최소한 순번, 시작·종료 정수 밀리초 TC, 음성 발화문, 화자, 불확실성, 화면 텍스트와 비전 근거 참조를 포함한다.
- 모든 cue는 `0 <= start_tc_ms < end_tc_ms <= 원본 재생 시간`을 만족해야 한다.
- 자동 처리가 끝난 뒤 미확정 cue가 있으면 작업을 `needs_confirmation`으로 두고 사용자에게 지금 확인을 진행할지 묻는다.
- 사용자가 확인하지 않겠다고 해도 현재 초본을 제공하며 나중에 같은 실행에서 재개할 수 있다.
- 사용자가 동의하면 미확정 cue를 한 번에 하나씩 질문한다.
- 각 질문은 내부 확인 ID, 대상 cue와 필드, 타임코드, 현재 값, 후보와 판단 근거를 포함한다. 사용자가 확인 ID를 직접 입력하도록 요구하지 않는다.
- 확인 요청, 사용자 답변과 적용 결과는 별도의 추가 전용 기록에 순서대로 보존한다.
- 잘못된 확인 ID, 동일 항목의 중복 답변, 빈 답변과 손상된 기록은 오류로 처리한다.
- 확인 처리 오류가 발생하면 기존 초본과 상태를 변경하지 않는다.
- 미확정 cue가 모두 해결되면 작업 상태를 `finalized`로 바꾸고 JSON·CSV를 다시 생성한다.
- 사용자에게 수정 이유나 오류 분류를 입력하도록 요구하지 않는다.

### 실행 산출물과 근거

- 실행 디렉터리에 원본 영상, 확보된 기존 자막, 오디오와 모든 추출 프레임·contact sheet·짧은 클립을 보존한다.
- 프레임 manifest는 각 파일의 `frame_id`, 원본 프레임 위치, `pts_ms`와 경로를 연결한다.
- 비전 판정은 사용한 프레임·contact sheet·클립을 manifest의 ID와 경로로 참조한다.
- 회차 맥락 원문과 에이전트가 정리한 등장인물 목록을 함께 보존한다.
- Sol·Terra의 판정, 확인 요청·답변·적용 기록, JSON 정본, 파생 CSV와 검증 결과를 실행 ID 아래에 보존한다.
- 앞서 열거한 근거와 모든 추출 시각 산출물을 보존하되, 캐시·재시도 조각 같은 임시 파일은 보존 대상으로 강제하지 않는다.
- 실패한 실행의 산출물은 완료 결과로 표시하지 않는다.

### 누락 발화

- VAD 음성 구간이 현재 cue로 충분히 덮이지 않으면 누락 후보로 본다.
- 짧은 내부 무음의 병합 기준과 cue 겹침 기준은 초기 구현 기본값으로 두고 실제 영상 결과에 따라 조정한다.
- 누락 후보는 잘린 단어를 판단할 수 있는 앞뒤 문맥과 함께 재전사한다.
- 확신할 수 있는 결과는 복원 발화로, 그렇지 않은 결과는 사용자 확인 항목으로 남긴다.

VAD 길이, 내부 무음, cue 겹침과 재전사 문맥의 구체적인 수치는 제품 계약이나
합격선으로 고정하지 않는다.

### 하단 화면 자막과 싱크

- 전체 영상 비전 감사가 장면 맥락과 함께 하단 자막 문구와 대략적인 표시 구간을 한 번에 판정한다.
- 화면 분석과 자막 판독을 서로 다른 비전 모델 호출로 나누지 않는다.
- Python은 비전 모델에 전달하는 모든 프레임에 `frame_id`, 원본 프레임 위치와 `pts_ms`를 붙인다.
- 비전 모델은 임의의 초나 프레임 번호를 계산하지 않고 제공받은 `frame_id`만 참조한다.
- 비전 판정은 화면 자막 문구, 처음·마지막으로 확인한 `frame_id`, 등장 경계의 앞뒤 `frame_id`, 소멸 경계의 앞뒤 `frame_id`와 confidence를 반환한다.
- 처음·마지막으로 확인한 프레임은 관찰 범위이고, 앞뒤 프레임 쌍은 실제 전환이 존재하는 경계 후보다.
- 전체 영상의 하단 픽셀 변화량을 자막 후보 탐색기나 확정 판정기로 사용하지 않는다.
- Sol이 반환한 대략적인 전환 구간 주변만 Python이 촘촘히 검사해 등장·변경·소멸 경계 후보를 좁힌다.
- 로컬 검사는 경계를 확정하지 않으며, 카메라 컷이나 움직임과 구분할 수 없으면 Terra 재검사나 사용자 확인으로 보낸다.
- 화면 자막 구간은 `[첫 표시 프레임 PTS, 첫 비표시 프레임 PTS)`로 정의한다. 영상 끝까지 표시되면 원본 재생 시간을 종료 TC로 사용한다.
- Python은 확정된 경계 프레임의 실제 PTS를 정수 밀리초 TC로 변환한다.
- 타임코드는 `프레임 번호 ÷ 평균 fps`로 계산하지 않는다. 가변 프레임률 영상에서도 원본 PTS를 기준으로 한다.
- 각 화면 자막 구간의 대표 프레임에서 비전 모델이 한국어 문구를 직접 읽는다.
- 화면 자막과 음성의 반복적인 의미 일치와 시간 오차의 안정성을 바탕으로 회차 단위 화면 자막 신뢰도를 `low`, `medium`, `high` 중 하나로 자동 추정한다.
- 사용자는 회차 맥락에서 자동 추정된 신뢰도를 덮어쓸 수 있으며 사용자 지정값이 우선한다.
- `low`에서는 화면 자막을 참고 자료로만 보존하고 cue TC를 바꾸지 않는다.
- `medium`에서는 대응 발화 탐색과 재전사 근거로 사용하되 cue TC는 오디오·VAD 경계를 유지한다.
- `high`에서는 화면 문구와 음성이 의미상 일치하고 오디오 경계가 불확실할 때 화면 자막 TC를 cue TC로 채택할 수 있다.
- 하나의 화면 자막이 여러 발화를 묶거나 한 발화를 여러 자막으로 나눌 수 있으므로 화면 자막 경계를 cue 경계로 강제하지 않는다.
- 어떤 신뢰도에서도 화면 자막 문구는 `음성 발화`를 덮어쓰지 않는다. 요약·의역·강조 문구는 `화면 텍스트`로 분리해 보존한다.
- 정렬 결과에는 음성 구간, 화면 자막 구간, 두 구간의 차이, 대응 근거와 confidence를 기록한다.
- 시청각 증거가 충돌하면 `large-v3` 재전사 또는 사용자 확인 대상으로 보낸다.
- 짧은 자막이나 빠른 전환은 더 촘촘한 contact sheet 또는 짧은 클립으로 다시 확인한다.

### 품질 목표

- 초기 개발 단계에서 CER, 화자 식별 정확도, 화면 자막 포착률, 처리 시간과 비용에 고정 합격선을 두지 않는다.
- 대표 영상 3~5개 검수는 초기 구현의 필수 완료 조건으로 삼지 않는다.
- 사용자가 결과를 실제로 검수한 뒤 현실적인 품질 목표를 별도 결정한다.
- 초기 버전은 검수 사유 기록, 오류 분류와 초본·수정본 자동 비교 기능을 제공하지 않는다.

## 테스트 결정

테스트는 사용자에게 보이는 결과와 Sol·Terra·Python 사이의 안정된 데이터
계약을 검증한다. 모델 호출 횟수·순서, 정확한 프레임 추출률, 파일·클래스
개수와 private 함수 구조는 고정하지 않는다. 시간 지연에 의존하지 않고
고정 fixture와 이벤트로 한 번의 실행에서 같은 결과를 내야 한다.

### 진입과 상태

- 올바른 URL은 실행 ID와 `waiting_context` 상태를 만들고, 잘못된 URL은 명확한 오류와 비정상 종료 코드로 거부하는지 검사한다.
- 회차 맥락이나 `없음`을 받기 전에는 ASR·비전 감사가 시작되지 않는지 검사한다.
- 자유 형식 맥락의 원문과 정리본을 같은 실행에 보존하고 다른 실행에 재사용하지 않는지 검사한다.
- `없음`에서도 작업을 계속하되 인물 이름을 추측하지 않는지 검사한다.
- 처리 모드를 요구하지 않고 모든 실행에서 동일한 전체 비전 감사 흐름을 수행하는지 검사한다.
- 일반 단계 실패에서 `failed` 상태, 실패 단계와 오류 메시지를 보여주고 기존 정상 초본을 바꾸지 않는지 검사한다.

### 입력과 누락 발화

- 기존 자막이 있으면 참고하고, 없거나 다운로드·해석에 실패하면 경고 후 ASR을 계속하는지 검사한다.
- 원본 영상이나 오디오를 준비하지 못하면 입력 준비를 실패 처리하는지 검사한다.
- 고정 미디어 fixture의 누락 음성을 문맥과 함께 재전사하고, 확신 가능한 결과만 JSON 정본에 자동 반영하는지 검사한다.
- VAD의 구체적인 길이·겹침·문맥 수치를 제품 합격선으로 테스트하지 않는다.

### 시각 감사와 타임코드

- 감사 구간이 원본의 시작부터 끝까지 전체 시간대를 덮고 모든 최종 cue와 VAD 음성 구간이 감사 근거에 연결되는지 검사한다.
- 각 cue의 수정 결과가 담당 구간 에이전트 하나에서만 채택되고 경계 cue는 인접 에이전트에 읽기 전용으로 전달되는지 검사한다.
- 프레임 manifest가 유효한 `frame_id`, 원본 프레임 위치, `pts_ms`와 파일 경로를 포함하는지 검사한다.
- 비전 판정이 manifest에 없는 ID나 순서가 뒤집힌 경계 프레임을 참조하면 거부하는지 검사한다.
- 장면 맥락과 하단 자막 문구를 함께 판정하고, 전역 하단 픽셀 변화만으로 자막 후보나 경계를 확정하지 않는지 검사한다.
- Sol이 찾은 대략 구간의 국소 검사가 경계 후보를 좁히고, 카메라 컷이나 움직임과 구분하지 못하면 Terra나 사용자 확인으로 보내는지 검사한다.
- 가변 프레임률 fixture에서 `[첫 표시 프레임 PTS, 첫 비표시 프레임 PTS)`를 정수 밀리초 TC로 만들고 평균 fps 계산을 사용하지 않는지 검사한다.
- `low`, `medium`, `high`의 TC 적용 규칙과 사용자 신뢰도 덮어쓰기가 지켜지는지 검사한다.
- 요약·강조 화면 문구가 음성 발화문을 덮어쓰지 않는지 검사한다.
- 비전 판정이 사용한 프레임·contact sheet·클립과 모든 추출 파일이 실행 디렉터리에 보존되는지 검사한다.
- 비전 모델이 화면 문구를 확정하면 별도 OCR을 생략하고, 확정하지 못한 구간에서만 OCR을 사용하는지 검사한다.

### 초본과 확인

- JSON 정본의 필수 cue 필드, 순번, 정수 타임코드와 재생 시간을 검사한 뒤 같은 cue 행의 CSV를 생성하는지 검사한다.
- 미확정 cue가 있어도 `workflow_status=needs_confirmation`, `validation=valid`인 JSON·CSV 초본을 제공하는지 검사한다.
- 미확정 cue가 있으면 확인 진행 여부를 먼저 묻고, 거절하면 현재 초본을 유지하며 나중에 재개할 수 있는지 검사한다.
- 동의하면 대상 cue·필드, 타임코드, 현재 값, 후보와 근거를 포함한 질문을 하나씩 제시하는지 검사한다.
- 확인 요청·답변·적용 결과를 추가 전용 기록에 남기고, 잘못된 ID·중복·빈 답변·손상 기록에서는 기존 초본과 상태를 바꾸지 않는지 검사한다.
- 모든 미확정 cue가 해결되면 JSON 정본과 CSV를 다시 만들고 `finalized`로 전환하는지 검사한다.
- 한 번에 여러 출력 오류가 있으면 모든 오류를 보고하는지 검사한다.

### 통합 검증

- 전체 처리 책임을 연결한 짧은 미디어 fixture 실행을 기준 통합 테스트로 둔다.
- 테스트 명령은 저장소에서 하나의 공식 명령으로 실행할 수 있어야 한다.
- 저장된 비전 판정 fixture로 기본 통합 테스트를 재현하고, 실제 비전 에이전트 실행은 별도 smoke test로 둔다.
- 실제 YouTube 네트워크 호출과 전체 `large-v3` 실행은 빠른 기본 테스트와 분리한다.
- 실제 영상 3~5개의 사람 검수는 정량 합격 테스트가 아니라 후속 품질 목표를 정하기 위한 운영 활동으로 남긴다.

- 번역 및 번역문 생성

- 최종 자막의 무인 자동 완성

- 초기 단계의 정량 품질·처리량 합격선과 대표 영상 검수를 구현 완료 조건으로 강제하는 것
- 외부 유료 ASR API 제공자 구현
- 등장인물 대표 사진 입력과 얼굴 참조 자료 관리

- 인물 관계·역할 정보 입력
- 30fps 원본 프레임 전체를 비전 모델에 그대로 전달하는 방식
- 웹 UI 또는 데스크톱 GUI
- 팀 단위 계정·권한·공유 기능
- 자동 번역·요약·콘텐츠 분석
