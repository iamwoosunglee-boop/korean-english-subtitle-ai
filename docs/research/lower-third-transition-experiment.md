# 하단 자막 전환 검출 실험

실험일: 2026-08-02
목적: 화면 하단 자막의 등장·변경·소멸 시점을 모델 호출 없이 찾거나 정밀하게 보정할 수 있는지 확인한다.

## 자료

- 저장소: TaT
- 영상 길이: 1,896.394초
- 해상도: 1920×1080
- 프레임률: 30000/1001fps
- 기존 1초 간격 하단 crop 프레임과 원본 MP4를 함께 사용했다.

## 프로토타입

1. 영상 하단 중앙 영역을 crop한다.
2. 4fps로 프레임을 추출한다.
3. 480×175 grayscale로 축소한다.
4. 밝은 글자 획의 변화를 강조하는 top-hat mask를 만든다.
5. 연속 프레임 mask의 변화량이 임계값을 넘으면 전환 후보로 기록한다.
6. 후보 전후 프레임을 사람이 직접 확인한다.

파일을 생성하지 않고 ffmpeg·OpenCV 파이프라인을 메모리에서 실행했다.

## 결과

### 수동 확인 표본

서로 다른 두 구간, 총 30초를 4fps로 확인했다.

| 항목 | 결과 |
|---|---:|
| 실제 전환 구간 | 12 |
| 검출 후보 | 16 |
| 맞게 검출 | 11 |
| 오탐 | 5 |
| 누락 | 1 |
| 정밀도 | 68.8% |
| 재현율 | 91.7% |
| 기본 시간 해상도 | 0.25초 |

자막 등장·변경·소멸은 대부분 검출됐다. 그러나 손·태블릿 움직임, 카메라 컷,
명찰과 고정 그래픽도 변화로 잡혀 오탐이 발생했다.

### 전체 영상

| 항목 | 결과 |
|---|---:|
| 처리 프레임 | 7,585 |
| 처리 시간 | 63.0초 |
| 전환 후보 구간 | 853 |

동일한 하단 crop을 ffmpeg만으로 처리한 별도 측정은 71.63초였다. 전체 영상
처리 속도는 충분했지만 후보가 분당 약 27개 생성돼, 각 후보를 별도 비전
호출로 보내는 방식은 비효율적이다.

### 정밀 보정

이미 대략적인 자막 전환 구간을 알고 있는 9.0~15.5초 구간을 10fps로
재검사했다. 실제로 보이는 주요 변화가 약 9.7초, 10.2초, 11.1~11.5초,
12.0초, 13.2초와 14.9초에서 포착됐다. 따라서 비전 감사에서 얻은 대략적인
구간 주변만 촘촘하게 검사하면 자막 경계를 0.1초 단위 후보로 좁힐 수 있다.

## 판정

하단 자막 전환 시점은 충분히 검출할 수 있다. 다만 전체 영상에서 픽셀
변화만으로 자막 전환을 확정하는 방식은 오탐이 많아 채택하지 않는다.

권장 흐름은 다음과 같다.

1. 모든 실행에서 수행하는 비전 감사가 장면 분석과 함께 하단 자막 문구와 대략적인 표시 구간을 한 번에 반환한다.
2. 별도의 자막 판독 모델 호출은 만들지 않는다.
3. Python CLI는 반환된 전환 구간 주변만 10fps로 다시 검사해 등장·변경·소멸 경계를 좁힌다.
4. 보정된 경계의 전후 대표 프레임을 기존 비전 감사 결과와 함께 메인 에이전트가 확인한다.
5. 카메라 컷이나 움직임 때문에 경계를 확정할 수 없으면 범위를 넓혀 다시 보거나 사용자 확인 대상으로 남긴다.

이 구조는 화면 분석과 자막 판독을 하나의 비전 호출로 유지하면서, 정밀
타임코드 보정은 토큰이 들지 않는 로컬 처리로 분리한다.
